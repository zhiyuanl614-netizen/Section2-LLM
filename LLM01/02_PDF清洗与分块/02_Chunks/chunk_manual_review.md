## 3. 发现

### 3.1 自动初筛结果

- 241 条中 **225 条**锚点可直接在对应页面原文中定位；**16 条**初筛未直接命中，逐条人工核实后，全部可归因于下列两类已知、非灾难性的原因，没有发现无法回溯到原文的证据块：
  - 多数属于 3.2 节描述的"软连字符吞词"缺陷（锚点词被拆成两段，如 `con tributions` vs 原文 `contributions`）；
  - 少数属于 3.3 节描述的公式区域阅读顺序错乱（锚点落在被打乱的公式片段上）。
- 未发现：重复 evidence_id、偏移越界、`source_excerpt` 与 `text` 不一致、跨 section 越界引用等问题（与 `chunking_manifest.json` 中记录的机械性 QA 结果一致）。

### 3.2 系统性问题 1：换行连字符被吞词（Step 1 遗留，影响证据文本质量）【建议修复】

原始 PDF 中大量跨行连字符断词（如 `con\xad\ntributions`，`\xad` 为软连字符，用于提示 `contributions` 一词跨行书写）在 Step 1 的清洗/重排逻辑中被错误处理：软连字符被丢弃，但换行应当被替换为"无空格拼接"而不是"插入空格"，导致输出文本中出现大量被拦腰截断的单词，例如（均为本次复核中逐一回溯 PDF 确认）：

| 原文（PDF） | 清洗后 evidence text | 出处 |
|---|---|---|
| contributions | con tributions | B001-PDF-01, 1.2 Contribution |
| interdependence | inter dependence | B001-PDF-01, 1.2 Contribution |
| sub-systems | sub-sys tems | B001-PDF-01, 1.2 Contribution |
| Linearized | Linear ized | B001-PDF-01, 2.1 |
| desalination | desali nation / desalina tion | B001-PDF-01 多处 |
| However | How ever | B001-PDF-01, 3.2.1 |
| effectiveness | effec tiveness | B001-PDF-01, 3.1 |

用脚本对 5 篇文献 Zone A–D 全文做前缀启发式扫描（非穷尽，仅覆盖常见英文前缀），**至少检出约 170 处**疑似同类断词，5 篇文献均有分布（PDF-01: 43，PDF-02: 26，PDF-03: 32，PDF-04: 28，PDF-05: 42）。这是一个**偏保守的下界估计**，实际发生率可能更高。

**影响评估：**
- 对人工阅读/语义理解影响较小（人眼可自动纠正），但对计划中的 **BM25 词法索引是实质性风险**：`contributions` 被拆成 `con` + `tributions` 两个独立 token 后，标准分词器不会再把它们等价于完整词 `contributions`，会直接导致包含该词的精确/BM25 检索失效（召回率下降），尤其是 D01–D10 中涉及"contribution/interdependence/desalination"等关键术语的检索。
- 对稠密向量 embedding 的影响通常较小（subword tokenizer 一般能从局部上下文恢复语义），但仍会轻微扰动句子表示。
- 这是 **Step 1 的清洗逻辑缺陷**，不是 Step 2 分块边界问题；按 README 的模块划分，修复点在 `step1_pdf_targeted_slicer.py` 的换行/软连字符处理规则，而非 `step2_evidence_chunker.py`。

**处理决定（本次）：** 不在复核阶段"猜补"缺失空格或静默修复文本（遵循 README"不得猜补"的原则），仅记录问题、给出量化范围和具体样例，留待与用户确认是否在进入 Step 3 索引前先修复 Step 1 并重跑 Step 1→Step 2。**在修复前，不建议冻结当前 `evidence_blocks.jsonl` 作为 BM25 索引的最终输入版本**（稠密向量索引受影响较小，可视情况单独推进）。

### 3.3 系统性问题 2：复杂公式区域的阅读顺序错乱（范围比 README 原标记的 2 块更广）【已知限制，不可静默修复】

README 仅点名复核 `B001-PDF-03-ZC-S12-3-3-C003/C004` 两块。本次复核确认这两块问题属实：PyMuPDF 按默认阅读顺序抽取多行分式/上下标公式（如 resilience 定义式 (15)-(20)）时，会把分子、分母、不同公式的片段交叉抽出，输出文本中变量、运算符与原始公式结构不对应（例如 C003 把公式 (15)-(20) 的分子分母、下标混排成一行乱序文本）。

**新发现：** 分层抽样过程中又额外发现至少 **6 处**同类问题，集中在公式密集的 Zone B/C 段落，不限于 PDF-03：

- `B001-PDF-03-ZB-S04-2-2-C004`（2.2 节依赖关系公式 (2)-(5)，变量与公式编号交叉错位）
- `B001-PDF-03-ZB-S09-3-2-1-C003`（Robustness 公式 (8)-(9) 片段错位）
- `B001-PDF-03-ZC-S12-3-3-C001`（Rapidity 公式 (12)-(14) 片段错位，与 C003/C004 同一问题家族）
- `B001-PDF-04-ZC-S20-E-C001`（Demand Satisfaction Resilience 公式 (15)-(16)，含多个 `⟦PDF_GLYPH_U+XXXX⟧` 占位符交织）
- `B001-PDF-04-ZC-S41-G-C001`（Load Supplied IOR 公式 (36)-(37)，求和/下标顺序错乱）
- `B001-PDF-02-ZB-S06-2-2-C002`（day-ahead 调度公式 (27)-(28)，变量下标重排）

**影响评估：** 这些 block 的纯文本**不能被当作公式的可信转录**用于 D02/D05/D06 等涉及"核心耦合方程""时间尺度"的证据抽取；若 Agent A/B 直接读取这些纯文本去判断方程含义，有误判风险。好消息是：这些块的叙述性说明句（方程前后的自然语言解释，如"where RR0 denotes..."）基本完整准确，仅公式本身的内部排布被打乱。

**处理决定：** 不在 Step 2 阶段用规则"猜复原"公式结构（高风险、易引入虚假内容，违反 README 的"不得猜补"原则）。建议：
1. 在 `evidence_blocks.jsonl` 的 schema 中为涉及公式密集区域的 block 增加 `formula_layout_risk: true` 标记（本次复核未改动 schema，仅在本文档记录受影响 ID 清单，供 Step 3/4 使用时参考过滤或人工核对原始 PDF/公式图像）；
2. Step 4 的 Agent A/B 在处理标记为高风险的 block 时，必须同时参照原始 PDF 页面图像核对公式，不能仅依赖抽取文本；无法核验的公式内容应按 README 既定规则标记 `evidence_unavailable`，不得由模型自行"补全"方程。

### 3.4 次要发现（不影响证据有效性，供参考）

1. **图注文字片段残留**：`B001-PDF-05-ZC-S12-3-1-C002` 块首为"Diagram of the PWS topology and dependencies for the Shelby."——实际是原文图注"Fig. 6. Diagram of..."的残段（缺少"Fig. 6."前缀），系 PDF 图注与正文混排、Step 1 未保留版面框所致（README 已知局限 #1/#4）。不影响证据可回溯性（`source_excerpt`/offset 均正确对应原文片段），但在生成式引用时应避免直接当作正文叙述引用。
2. **Zone C/D 边界的合理判断**：`B001-PDF-01-ZD-S09-3-1-C001`（3.1 Test system，描述仿真案例设置）被标为 Zone D，而紧邻的 3.2.1 节（结果分析）被标为 Zone C。经核对原文，3.1 节内容是案例/测试系统设定说明，归入 Zone D（案例）、3.2.1 节归入 Zone C（指标/仿真结果分析）的区分是合理的工程判断，不是分类错误，予以确认保留。
3. **4 个短块（<40 词）** 经核对 PDF 原文，均为合理的独立句子或小节收尾句（如"According to the above simulation parameters, the MG integrating WSSs is tested. The results are as follows:"），不存在因分块规则导致的错误截断；`B001-PDF-03-ZB-S10-3-2-2-C001` 短块文本本身受 3.3 节所述公式错位问题影响，但其短小是原文结构使然（小节仅含两行公式起始部分），不是分块算法的缺陷。
