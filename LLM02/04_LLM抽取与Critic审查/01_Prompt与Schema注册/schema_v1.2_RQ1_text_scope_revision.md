# Schema v1.2 范围修订：RQ1 的文本证据边界

- **修订日期：**2026-10-08
- **状态：**已启动的工作版本；完成 D01/D02 文本证据 pilot 与机械校验后再冻结。
- **上游范围依据：**用户于2026-10-08确认，公式转录/推导不属于当前研究分析；原 PDF、Step 1 文本、239条 evidence blocks 和 `formula_layout_risk` 元数据均保留。公式风险块中的清晰叙述可作为文本证据，但不得据公式结构作结论。
- **本文件用途：**非破坏性版本修订；旧 `schema_v2.json`（schema_version v1.1）、v1.0冻结快照及既有抽取/评估产物均不覆盖。

## 1. 方法决定与研究目标对齐

**研究总目标、RQ层级和三项候选 gap/frontier 方向不因本次代码本修订而改变。** 项目仍遵循“通过领域文献学习提出三项候选研究差距/前沿方向 → 据此提出研究问题/假设 → 由大语言模型基于可回溯文本证据进行验证”的主线。当前5篇 PDF 是先导/试点语料；D01–D10是操作化观察维度，不是要求每一维在这5篇中都出现的配额。某标签在小样本中为零或未出现是正常的样本结果，不能据此删掉 RQ、否定候选方向或推断整个领域不存在该现象。

本 v1.2 **只修订证据操作化和公式处理边界**：D01/D02限于可独立支持判断的自然语言证据；旧 D03“核心耦合方程类型”不编码，因用户已确认不做公式转录/推导；不在看到现有5篇结果后再创造一个貌似等价的文本类别。方程类别、编号、变量、上下标、数学结构、推导及方程方向均不编码、不评估，也不纳入指标或结论。D03范围外不等同于删除 RQ1 中更广泛的模型/耦合研究问题，也不等同于取消三项候选方向。

**RQ1在研究设计层面保持原定义**：“现有水—电耦合研究如何表征水—电耦合方向、厂内冷却水和核心耦合方程？” 本轮只意味着其“方程类型/数学结构”子维度暂不通过 D03 进行验证；当前可由 D01/D02及其他文字证据支持的部分仍可分析。凡结论必须依赖方程本身才能成立，均须明示为当前证据范围外，不得用乱码公式推断。

因此，v1.2不是缩减总体研究目标，而是**在保留研究主线和三项候选方向的前提下，标明哪些问题能由当前文本证据验证、哪些公式层主张暂不评估**。不删改任何源数据。

## 2. D01：水—电耦合方向（文本证据版）

### 可用标签

- `Water_to_Power`：论文自身方法/模型的清楚自然语言描述明确指出供水状态、供水能力或水侧运行影响电力系统运行/发电/调度。
- `Power_to_Water`：清楚文字明确指出电力可用性、电价、调度或电侧故障影响供水系统运行。
- `Bidirectional_Coupled`：作者自身方法/模型的文字分别支持两个方向；不能只因摘要称“interdependent”就推断双向。
- `Parallel_No_Explicit_Textual_Coupling_Statement`：全文相关文字仅并列讨论两系统，未找到作者自身方法/模型的明确耦合方向表述。该标签**只说明文本中未陈述耦合方向，不表示论文没有方程或数学耦合**。

### 编码规则

1. 只引用可读的自然语言陈述。若同一 evidence block 含公式乱码，只能引用能独立支持判断的完整叙述句。
2. `Cited_Other_Work` 不能单独支撑主标签；只使用本文自身方法，或本文明确采用并实现的被引方法。
3. 若方向判断只能通过查看/推导公式才能得到，记 `Out_Of_Scope_Formula_Only`，不能猜测，也不能将其记作 `Not_Stated_In_Text`。
4. 不记录方程号、方程变量、数学结构或“方程证明了某方向”等结论；`equation_detail` 留空。

## 3. D02：厂内冷却水建模（文本证据版）

### 可用标签

- `Explicit_InPlant_Cooling_Model_Described`：作者自身方法/案例的可读文字明确说厂内冷却水过程或需求作为模型输入、状态、约束、供水/控制对象或性能指标被纳入。无需转录或解释公式。
- `Generic_Water_Network_Only`：本文自身模型的可读文字描述了通用城市/配水网络，但完整阅读现有文本后未发现厂内冷却过程被纳入本文模型；若正文仅提到冷却水作为背景而非模型对象，应改用下一标签。
- `Both_Present`：可读文字同时明确描述通用水网和厂内冷却水过程均被纳入本文方法/模型。
- `Mentioned_Only_Not_Modeled`：冷却水只在背景、示例、局限或未来工作文字中出现，本文自身模型的可读文字未表明其被纳入。

### 编码规则

1. “纳入模型”的判断须由正文的自然语言说明支持；不以方程、参数符号或乱码公式本身作为依据。
2. 若冷却过程是否建模只能从未分析的数学结构判断，记 `Out_Of_Scope_Formula_Only`，不把“公式无法辨认”误作“论文未建模”。
3. 清楚的叙述性定义/解释即使位于 `formula_layout_risk=true` 块中仍可引用；公式本身及公式周边的变量关系不得作为证据。
4. `equation_detail` 留空。参数只有在文字中明确写出、且对当前标签必要时才可作为普通文本引用，不要求逐个提取或核验公式参数。

### 边界判据：通用水供给依赖 vs. 厂内冷却模型

如果论文的多层网络/依赖模型把“电厂由供水设施供水”作为一般节点/边依赖，并把冷却仅作为该依赖的示例，但没有说明冷却专属水量/流量需求、热过程、厂内状态或约束、控制对象或冷却性能指标，则：

- 可据清楚文字承认一般水到电力设施的依赖关系已被描述/建模（归入适用的耦合方向或依赖判断）；
- D02仍按“是否描述了厂内冷却专属过程/需求建模”判断，不因存在一条通用依赖边就自动判 `Explicit_InPlant_Cooling_Model_Described`；按当前阈值可判 `Mentioned_Only_Not_Modeled`，并在 `mechanism_judgment` 中明确注明“通用水—电依赖有建模，冷却专属过程未描述”；
- 不得将该 D02 标签扩写成“论文没有任何水—电依赖”或“冷却绝未出现在模型叙述中”。若项目专家另行裁定通用供水依赖已达到冷却模型阈值，应先版本化调整定义，再对全部文献一致重判。

该边界在 PDF-03 中出现，当前仍需领域专家确认其构念阈值；此注释用于记录一致的暂行规则，不声称独立专家已裁定。

## 4. D03：方程类型（退出分析）

- `D03` 在 v1.2 中保留一个**范围状态记录**：`primary_label = Not_Analyzed_Out_Of_Scope`。
- `mechanism_judgment` 固定说明：“方程类型分析按当前研究范围未执行；这不表示该论文没有方程，也不对方程类型作判断。”

- 该状态不是 `Not_Stated_In_Text`、`Evidence_Unavailable` 或负面发现；不得将其改写成“无方程”或“定性模型”。
