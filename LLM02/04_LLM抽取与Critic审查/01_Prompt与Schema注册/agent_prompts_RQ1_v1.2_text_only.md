## Agent A — D01/D02（v1.2）

仅分析论文作者对其自身方法/模型的**清晰自然语言叙述**：

1. 对 D01，判断文字是否明确描述水→电、电→水、双向，或仅并列讨论而没有文字耦合方向说明。
2. 对 D02，判断文字是否明确描述厂内冷却水过程/需求进入本文模型，还是仅描述通用水网、背景提及或完全未涉及。若模型只表示“电厂由供水设施供水”这一通用节点/边依赖、并把冷却仅作为示例，但未描述冷却专属需求/过程/状态/约束/控制/性能，不自动等同于厂内冷却过程已建模；D02按冷却专属过程阈值标注，同时明确承认一般水—电依赖已建模，不得把 D02 标签扩写为“没有任何水—电依赖”。PDF-03为该边界案例，需保留不确定性。
3. 可引用含公式风险标记块中的清楚叙述句，但必须保证该句脱离公式结构也足以支撑标签。
4. 不读取/转录/比较公式，不推导变量、上下标、方程方向、参数关系或编号。不得依据公式乱码、方程编号附近的片段或数学常识补足论文未写出的叙述。
5. 若一项判断必须依赖方程结构而非清楚文字，使用 `Out_Of_Scope_Formula_Only` 并解释范围边界；不可将其写成 `Not_Stated_In_Text` 或“未建模”。
6. D01/D02 的 `equation_detail` 必须为空。D03 固定为 `Not_Analyzed_Out_Of_Scope`，不做任何逐文献方程判断，不提供方程证据、标签或数学解释。
7. 证据引用必须逐字匹配当前239版 evidence block；`section_id`、PDF物理页序和 `evidence_id` 均据原块填写。只引用实际可读的自然语言片段。

## Agent B — 范围与证据审查（v1.2）

对每条 D01/D02 记录复核：

- **Scope check：**结论是否完全基于自然语言；有没有依赖公式、变量符号、方程编号或公式版面推断？若有则退回。
- **Own-method check：**证据是否描述本文自身模型，而非背景综述/被引方法？
- **Entailment check：**被引文本是否充分支持耦合方向或冷却水建模标签？特别检查“interdependence”等宽泛词是否被错误扩张为双向。
- **Cooling-model distinction：**冷却水作为案例/背景示例，不等于厂内冷却过程已建模；但通用节点/边供水依赖仍可能已建模。分别记录这两个层次，不得把“D02无冷却专属过程模型”写成“没有水—电依赖”。须找到方法、案例或结果中的明确文字依据。
- **Evidence check：**原句、块ID、章节和页码可回溯；公式风险块只核验被引叙述句，不评价公式。
- **Out-of-scope check：**若只有公式能支持判断，应标为 `Out_Of_Scope_Formula_Only`；不得改写成文本未提及、证据不存在或公式不存在。

D03 的 `Not_Analyzed_Out_Of_Scope` 是项目范围状态，不是论文标签；Agent B 不得把它改成“无方程/定性模型”。

## 执行与披露

本补丁用于建立一个可审计的 text-only 复核批次。除非另行记录真实、隔离的不同执行者，本项目中 Agent A/B 仍由同一会话渠道完成；任何产出须标注为 Agent 辅助复核，不得称为独立双模型或独立领域专家盲审。
